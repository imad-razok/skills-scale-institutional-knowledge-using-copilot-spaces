# OctoAcme Onboarding Checklist by Role

## Purpose
Provide role-specific onboarding checklists to help new team members quickly understand their responsibilities, key contacts, and first contributions in the context of OctoAcme project management.

---

## Developer Onboarding

### Week 1: Foundation
- [ ] Review OctoAcme Project Management Overview
- [ ] Review OctoAcme Roles and Personas to understand the team
- [ ] Clone repository and set up development environment
- [ ] Review Definition of Done and branching conventions
- [ ] Attend sprint planning or kickoff meeting
- [ ] Identify technical lead and assigned reviewer(s)
- [ ] Review current project backlog and roadmap
- [ ] Set up 1:1 with team lead

### Week 2-3: Immersion
- [ ] Complete first code review or pair programming session
- [ ] Submit first pull request with guidance from reviewer
- [ ] Understand test coverage standards and add tests
- [ ] Participate in daily standups
- [ ] Review CI/CD pipeline and automated tests
- [ ] Understand deployment process and rollback procedure
- [ ] Review security and compliance checklist

### Week 4: Independence
- [ ] Independently complete a small backlog item
- [ ] Participate in sprint review and retrospective
- [ ] Document lessons learned or process improvements
- [ ] Schedule follow-up 1:1 to discuss progress and feedback

## Product Manager Onboarding

### Week 1: Foundation
- [ ] Review OctoAcme Project Management Overview
- [ ] Review OctoAcme Roles and Personas
- [ ] Meet with Product Lead (if applicable) and Project Manager
- [ ] Review current product roadmap and backlog
- [ ] Understand success metrics and how they're tracked
- [ ] Review stakeholder list and communication plan
- [ ] Understand customer/user personas and pain points
- [ ] Review recent retrospectives and action items

### Week 2-3: Context
- [ ] Attend backlog refinement session
- [ ] Participate in sprint planning
- [ ] Meet with key stakeholders to understand their priorities
- [ ] Review user research and data dashboards
- [ ] Understand technical constraints and capacity
- [ ] Learn the release cycle and deployment process

### Week 4: Ownership
- [ ] Lead backlog prioritization or refinement session
- [ ] Draft or update acceptance criteria for a feature
- [ ] Present roadmap or priority update to stakeholders
- [ ] Participate in sprint review and retrospective
- [ ] Schedule follow-up 1:1 with Product Lead

## Project Manager Onboarding

### Week 1: Foundation
- [ ] Review OctoAcme Project Management Overview
- [ ] Review OctoAcme Roles and Personas
- [ ] Understand the current project charter and one-pager
- [ ] Review project timeline, milestones, and key dates
- [ ] Meet with team leads (Product, Engineering, QA)
- [ ] Review risk register and dependencies
- [ ] Access project board and communication channels
- [ ] Set up recurring meetings (standups, syncs, reviews)

### Week 2-3: Operations
- [ ] Facilitate sprint planning or project planning session
- [ ] Attend daily standups and track progress
- [ ] Review burndown and velocity metrics
- [ ] Understand escalation paths and when to trigger them
- [ ] Review communication templates and status reports
- [ ] Meet with stakeholders to understand their information needs

### Week 4: Leadership
- [ ] Run a weekly status update or stakeholder sync
- [ ] Lead a retrospective or retrospective follow-up
- [ ] Identify and propose a process improvement
- [ ] Review and update risk register
- [ ] Schedule follow-up 1:1 to discuss early feedback

- [ ] Review OctoAcme Project Management Overview
- [ ] Review OctoAcme Roles and Personas

- [ ] Review Definition of Done and acceptance criteria examples

## Operations / DevOps Engineer Onboarding

### Week 1: Foundation
- [ ] Review OctoAcme Project Management Overview
- [ ] Review OctoAcme Roles and Personas
- [ ] Understand infrastructure architecture and topology
- [ ] Review CI/CD pipeline, deployment process, and automation
- [ ] Meet with Technical Lead and Developers
- [ ] Access infrastructure and monitoring dashboards
- [ ] Review runbooks, disaster recovery, and incident procedures
- [ ] Understand security and compliance requirements

### Week 2-3: Operations
- [ ] Attend sprint planning to understand deployment needs
- [ ] Execute a deployment to staging or production (with guidance)
- [ ] Review monitoring, alerting, and incident response
- [ ] Understand capacity planning and scaling considerations
- [ ] Document or update infrastructure documentation
- [ ] Participate in post-deployment verification

### Week 4: Ownership
- [ ] Lead or co-lead a deployment
- [ ] Propose an infrastructure improvement or automation
- [ ] Review and update runbooks or operational procedures
- [ ] Conduct a post-incident review or retrospective
- [ ] Schedule follow-up 1:1 to discuss operational readiness
